## 二、前后端架构说明（本系统不是纯前端演示）
本系统**有真实后端和数据库**，大后台与工作台已前后端连通：

| 层次 | 技术 | 说明 |
|---|---|---|
| 数据库 | PostgreSQL 14 | 按报告设计严格建库，**32 张表**，含泛化父子表（医生/前台绩效）、组合级联、聚合可空、两个中间表；三家门店演示数据 |
| 后端 API | Python（systemd 服务 `clouddent-api`） | 部署在狗云服务器 `206.237.21.229`，监听 `127.0.0.1:8600`；`POST /api/login` 发放 Bearer token；`GET/PUT /api/state` 读写全部业务数据；`GET /api/health`、`GET /api/tables` |
| 权限 | 服务端强制校验 | token 认证；无 token 401、伪造 token 401、越权操作 403；角色权限矩阵在服务端执行，不依赖前端隐藏 |
| Web 服务器 | nginx | 静态网页 + `/api` 反向代理到后端服务 |
| 前端 | 原生 HTML/JS（单文件自包含） | 大后台与工作台在 http 环境调用云端 API；用 `file://` 直接打开时自动回退本地演示数据 |
| 小程序 | 微信原生小程序（wxml/wxss/js） |  |

**数据流**：网页操作 → `/api/state` PUT（带 token）→ 后端对账写回 32 张真表；页面加载 → `/api/state` GET → 从多表 JOIN 装配前端数据。例如：发起跨店调阅申请写入申请记录、前台审核后生成 7 天只读有效期、医生查看调阅结果，全部落库可查。

**软件运行环境需求**：Linux 服务器（Ubuntu 22.04）、PostgreSQL 14、Python 3 + psycopg2、nginx、systemd；微信开发者工具（仅预览小程序时需要）。
